# MQTT Multi-Broker Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Multiple named MQTT brokers; each device publishes to any subset of brokers with independent per-(device, broker) configs; broker failures/reconnects are isolated per broker. (Issue #87)

**Architecture:** Single `MqttAdapter` managing `dict[broker_id, aiomqtt.Client]`; publish tasks keyed by `(device_id, broker_id)`. Clean-break API: `/system/mqtt` single-settings endpoints replaced by `/system/mqtt/brokers` CRUD; frontend updated in the same PR. Spec: `docs/superpowers/specs/2026-07-18-mqtt-multi-broker-design.md`.

**Tech Stack:** FastAPI, SQLAlchemy 2.0 async, Alembic, aiomqtt, pytest-asyncio; React 18 + TS + Ant Design 5.
